# UA Losses Crawler — Implementation Plan

**Date:** 2026-09-06  
**Goal:** Collect all soldier profile URLs from [ualosses.org](https://ualosses.org) despite the ~499-page pagination cap (~100 records/page).

---

## Problem

- Total records: ~213k soldiers.
- Unfiltered listing caps at page 499 (~49,900 visible records).
- `sort=last_name&direction=asc` works for all records; `last_name=<filter>` is a **substring** search (not prefix-only on the server).

## Strategy (adaptive prefix tree)

Instead of blindly splitting into all two-letter combos (`aa`–`zz`), use a **top-down adaptive split**:

1. Try a **single-symbol filter** for each symbol in the alphabet (see below).
2. If `ceil(found / 100) <= 499` → crawl that bucket directly.
3. If `> 499` → subdivide into **child prefixes** = `parent + symbol` for each alphabet symbol, recurse.
4. If a child still exceeds 499 pages → warn and subdivide to 3 symbols, etc.

### Observed single-symbol page counts (2026-09-06)

| Filter | Found | Pages (~found/100) | Action |
|--------|------:|-----------------:|--------|
| `z` | 22,592 | 226 | crawl as 1-symbol |
| `'` | 37,970 | 380 | crawl as 1-symbol |
| `-` | 166 | 2 | crawl as 1-symbol |
| `g` | 2 | 1 | crawl as 1-symbol (substring; few start with `g`) |
| `x` | 0 | 0 | skip |
| `a` … `f`, `h` … `y` | (TBD) | likely >499 for common letters | subdivide |

Examples:
- [last_name=z](https://ualosses.org/en/soldiers/?page=1&sort=last_name&direction=asc&last_name=z) — 226 pages
- [last_name='](https://ualosses.org/en/soldiers/?page=1&sort=last_name&direction=asc&last_name=%27) — 380 pages
- [last_name=-](https://ualosses.org/en/soldiers/?page=1&sort=last_name&direction=asc&last_name=-) — 2 pages
- [last_name=x](https://ualosses.org/en/soldiers/?page=1&sort=last_name&direction=asc&last_name=x) — 0 results

## Alphabet for prefixes

```python
LETTERS = "abcdefghijklmnopqrstuvwxyz"
SYMBOLS = "'-"  # apostrophe (Ukrainian softening), hyphen (compound surnames)
ALPHABET = LETTERS + SYMBOLS  # 28 symbols total
```

Child prefixes of parent `P`: `[P + s for s in ALPHABET]`.

**Comparison:** always lowercase both the prefix and the extracted last name before matching.

**Apostrophe in names:** display text is canonical (not URL slug).  
Example: slug `fodorov-...` vs display **`F'odorov Serhij Viktorovych`**.  
Prefix `f'` must match `F'odorov`; prefix `fo` must not.

**Hyphen in names:** compound surnames like `Alekper-Zade` — the last name is the first whitespace-delimited token (`Alekper-Zade`). Prefix `-` at position 0 is unlikely but checked anyway.

**Transliteration:** not a concern; site uses Latin only.

## Per-prefix crawl algorithm

**Input:** prefix string `P` (e.g. `"ni"`, `"f'"`, `"z"`).  
**Query params:** `sort=last_name`, `direction=asc`, `last_name=P` (substring filter).

### Step A — probe

1. Fetch page 1; parse `Found: N people` (reuse `_parse_people_count`).
2. If `N == 0` → done for this prefix.
3. `page_size = 100` (fixed).
4. `max_page = min(499, ceil(N / 100))`.
5. If `ceil(N / 100) > 499` → **warn**, enqueue child prefixes `P + s` for each `s in ALPHABET`, return (do not crawl at this depth).

### Step B — binary search for first relevant page

Find the **first page** where **any** record’s last name starts with `P` (case-insensitive).

```
lo, hi = 1, max_page
first_page = None
while lo <= hi:
    mid = (lo + hi) // 2
    records = fetch_listing_page(mid)
    if records is empty or 404:
        hi = mid - 1
        continue
    if any(record.last_name.lower().startswith(P.lower()) for record in records):
        first_page = mid
        hi = mid - 1
    else:
        # entire page is before the P* block (compare last record on page)
        if records[-1].last_name.lower() < P.lower():  # lexicographic, lowercased
            lo = mid + 1
        else:
            # page has substring matches but none starting with P; still before block
            lo = mid + 1
```

**404:** treat as out-of-range; shrink search upper bound.

**Sparse prefixes** (e.g. `zh`): first matching page may be the only page with matches; binary search still works.

### Step C — sequential forward scan

From `first_page` to `max_page`:

```
records = fetch_listing_page(page)
if records[0].last_name.lower() >= next_prefix(P):
    break   # past the P* block (see below)
for record in records:
    if record.last_name.lower().startswith(P.lower()):
        urls.add(record.url)
```

### Stop condition — `next_prefix(P)`

After the last name starting with `P`, the next alphabetical group begins.  
Stop forward scan when the **first record on the page** satisfies:

```
record.last_name.lower() >= next_prefix(P)
```

`next_prefix(P)` = smallest string strictly greater than all strings with prefix `P`, using ASCII/lex order on lowercased last names:

```python
def next_prefix(p: str) -> str:
    """Return upper bound for names starting with p."""
    if not p:
        return ""
    p = p.lower()
    # Increment last character; if it wraps past alphabet symbols, carry left
    chars = list(p)
    i = len(chars) - 1
    while i >= 0:
        idx = ALPHABET.index(chars[i]) if chars[i] in ALPHABET else -1
        if idx >= 0 and idx < len(ALPHABET) - 1:
            chars[i] = ALPHABET[idx + 1]
            return "".join(chars)
        chars[i] = ALPHABET[0]  # carry
        i -= 1
    # All chars wrapped — append ALPHABET[0] or return sentinel above any name
    return p + ALPHABET[0]
```

**Example:** `P="ni"` → stop when first record `>= "nj"`.  
**Example:** `P="nz"` → stop when first record `>= "n'"` (since `'` follows `z` in `ALPHABET`).  
**Example:** `P="z"` → stop when first record `>= "{"`  (char after `z` in ASCII) **or** use carry logic to produce `"z'"` / `"za"` as appropriate — **verify against live data during implementation**.

> **Implementation note:** validate `next_prefix` edge cases (`z`, `'`, `-`) on 2–3 live prefixes before full crawl.

### Step D — deduplication

Global `set[str]` of URLs across all prefixes. Same soldier may appear in overlapping substring filters; keep unique URLs only.

## Listing page parsing

### Canonical last name source

Parse from **visible card text**, not URL slug.

HTML pattern (from live pages):

```html
<li>
  <a href="/en/soldier/..."><b>F'odorov Serhij Viktorovych</b></a>
  ...
</li>
```

**Extraction:**

1. Select soldier list items (inspect DOM — likely `ul` list under results; confirm selector in spike).
2. For each item: read display name from the bold / title element.
3. **Last name** = first whitespace-delimited token of display name.  
   - `F'odorov Serhij Viktorovych` → `F'odorov`  
   - `Alekper-Zade Roman Olehovych` → `Alekper-Zade`
4. **URL** = absolute soldier profile link.
5. Store as `SoldierListItem(last_name: str, url: str)`.

### Step 6 — adaptive prefix planner

```python
def plan_prefixes() -> list[str]:
    """Return flat list of prefixes to crawl (depth-first expansion)."""

def expand_prefix(parent: str) -> list[str]:
    return [parent + s for s in ALPHABET]
```

**Root crawl:**

```
urls = set()
for symbol in ALPHABET:
    count = get_found_count(last_name=symbol)
    if count == 0:
        continue
    if needs_subdivide(count):
        for child in expand_prefix(symbol):
            urls |= crawl_prefix(child)   # recursive subdivide
    else:
        urls |= crawl_prefix(symbol)
return sorted(urls)
```

Alternatively: BFS queue of prefixes; worker processes each.

## Request budget estimate

- Root: 28 symbol probes (page 1 only) ≈ 28 requests
- Per prefix: ~`log2(max_page)` binary search + pages in `P*` block
- Typical 2-char prefix: ~8 + 5–50 ≈ 15–60 requests
- Worst case (676 two-char prefixes at depth 2 for busy letters): ~10k–20k requests total
- With 0.5s delay: ~1.5–3 hours
